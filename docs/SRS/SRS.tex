\tocsection{Glossary}
\label{sec:glossary}

\plt{Define every domain term and acronym used in this document, in
alphabetical order. Define a term once, here, and use it consistently
everywhere else. Where a term has a good external definition, link to it and
cite the source.}

\plt{Tip from the source template: define a \texttt{\textbackslash hypertarget}
for each glossary entry and a macro such as \texttt{\textbackslash newcommand\{\textbackslash Term\}\{\textbackslash hyperlink\{glossary-term\}\{Term\}\}}
so each use of the term in the body links back to its definition.}

\begin{itemize}
    \item \textbf{Term} -- Definition.
    \item \textbf{Acronym (Expansion)} -- Definition.
    \item \textbf{LLM (large language model)} -- An artificial intelligence model that is trained on a large dataset of text and is used to generate text.
    \item \textbf{Inference} -- The process of using an LLM to generate text.
    \item \textbf{Model layer partitioning} -- The distribution of an LLM's layers across a device pool.
    \item \textbf{Lake} -- A decentralized network of devices that work together to serve LLM inference via model layer partitioning.
    \item \textbf{Node} -- A participating device within the Lake network.
    \item \textbf{Device pool} -- A collection of nodes that comprise the Lake network.
    \item \textbf{Weights} -- The parameters of an LLM that determine its behavior when generating text.
    \item \textbf{Quantization} -- The process of converting an LLM's weights to a lower precision format to reduce memory usage.
    \item \textbf{Activation} -- An intermediate value that is computed during the text generation of an LLM.
    \item \textbf{KV cache} -- The cache of key-value pairs that are used to store the activations of an LLM.
    \item \textbf{Token} -- A unit of text that is processed by an LLM, typically a word or a subword.
    \item \textbf{Token throughput} -- The number of tokens that can be generated by an LLM per unit time.
    \item \textbf{Latency} -- The elapsed time between the start of an inference request and a defined event, such as the completion of the first token, or the completion of the entire response.
    \item \textbf{Coordinator} -- A program that manages the communication between the individual nodes in the device pool.
    \item \textbf{Session} -- A unit of interaction between a user and Lake to serve one or more inference requests.
\end{itemize}

\pegschapter{E}{Environment}

\plt{The Environment chapter describes the world the system operates in and
cannot change: physical constraints, other systems, rules of the domain. These
hold whether or not the system is built.}

\subsection{Glossary}\label{subsec:glossary}
The glossary has been moved to the front of the document (see the
\hyperref[sec:glossary]{Glossary} and the Changes from Original SRS Meyer
Template).

\subsection{Environment Components}\label{subsec:environment-components}
\plt{Elements of the environment that may affect or be affected by the system
and the project, including other systems the system must interface with,
hardware it runs on, and the people who operate it.}

\begin{itemize}
    \item \textbf{Inference users (a.k.a users)} -- Individuals who interact with the Lake network to serve inference requests.
    \item \textbf{Lake operators} -- Individuals who manage the Lake network, including the device pool and the model.
    \item \textbf{Device owners} -- Individuals who contribute one or more nodes towards the device pool.
    \item \textbf{Operation systems and drivers} -- Windows, macOS, and Linux operating systems that have the supported drivers to facilitate inference requests. Android and iOS operating system support is a stretch goal.
    \item \textbf{Network equipment} -- Routers, switches, thunderbolt cables, and any other hardware necessary to connect the nodes to the network. Connectivity via wifi is a stretch goal.
    \item \textbf{Model} -- Pre-trained and open-source model weights that is permitted to be downloaded and utilized by the Lake network via model layer partitioning.
    \item \textbf{External API consumers} -- Other services that utilize the Lake API to serve inference requests. This acts as the main interface for consumers to use Lake, such as coding agent harnesses (e.g. Claude Code, Codex, Pi).
 
\end{itemize}

\subsection{Constraints}\label{subsec:constraints}
\plt{Obligations and limits imposed on the system by the environment:
regulations, physical limits, resource limits, deadlines. These are not
design choices; the system must live with them.}

\begin{itemize}
    \item \textbf{Device hardware} -- Each node should have a sufficient CPU, GPU, memory, and storage such that its assigned model layers, KV cache, and other Lake software components can fit and run within the device, such that distributed inference has both a higher token throughput and lower latency than an equivalent single-device inferenece.
    \item \textbf{Network communication} -- Network communication, whether wired or wireless should have a sufficiently high bandwitch and low latency such that distributed inference has a token throughput and lower latency than an equivalent single-device inference.
    \item \textbf{Platform compatibility} -- Nodes within the Lake network must operate on Windows, macOS, and Linux, (as well as Android and iOS as stretch goals) as hardware acceleration and inference platforms are limited by the available drivers on this operating systems.
    \item \textbf{API compatibility} -- Lake must implement a standardized OpenAI API spec such that existing external clients can easily utilize Lake.
    \item \textbf{Model architecture} -- Only supported LLM architectures that Lake's model layer partioning supports can be used.
\end{itemize}

\subsection{Assumptions}\label{subsec:assumptions}
\plt{Properties of the environment that the system relies on but cannot
enforce. Each assumption is a risk if it turns out false; cross-reference the
Hazard Analysis where relevant.}

\begin{itemize}
    \item \textbf{Device owners authorize their nodes for use} -- Device owners have authorized their device to be used in the Lake network as a node for serving inference.
    \item \textbf{Participating nodes are trusted devices within the Lake network} -- Each node is trusted to run and process potentially sensitive inference data.
    \item \textbf{Permitted model use} -- Lake operators are using permitted models for inference that adhere to the respective licensing.
    \item \textbf{Network reachability} -- Nodes within the Lake network must be able to communicate over a network connection.
    \item \textbf{Model suitability} -- Models that are suited for a given task are used when Lake is serving inference (e.g. a larger model for logic/coding-based tasks, a smaller model for conversational tasks).
\end{itemize}

\subsection{Effects}\label{subsec:effects}
\plt{The ways the system changes its environment once deployed: effects on
users, on other systems, on resources.}

\begin{itemize}
    \item \textbf{Resource usage} -- Device owner's CPU/GPU, memory, and disk usage will increase while the device is part of the Lake network, potentially making the device too resource constrainted to multi-task or perform other activities. When not in use, any cached data or the stored layers can continue to utilize disk space.
    \item \textbf{Energy usage} -- Devices will consume more power, increasing energy usage, heat generated, fan usage, and decreasing battery life if unplugged.
    \item \textbf{Network bandwith usage} -- The Lake network may utilize a large amount of a network's bandwith, inhibiting other devices or processes from accessing the network.
    \item \textbf{Logged data} -- During inference, logs and other diagnostic information can be stored and persist on the node's disk.
    \item \textbf{Access to inference} -- Users can gain access to inference that they previoously would not be able to get within a single device or with a paid service.
\end{itemize}

\subsection{Invariants}\label{subsec:invariants}
\plt{Properties of the environment that must remain true throughout the
system's operation, and that the system must preserve.}

\begin{itemize}
    \item The provided model must remain unchanged. Loading the model and partioning its layers must not mutate the underlying model weights.
    \item Inference must be contained within the Lake network, and must not be sent to 3rd-party services.
    \item All nodes within the Lake network must be using compatible layer partitions that originate from the same model's layers.
    \item All nodes must serve inference in a way that the activations are performed in the identical order of how single-device inference is performed.
    \item Intermediate data from one request must not be used for another seperate request.
\end{itemize}

\subsection{Standards and Legal/Regulatory Factors}\label{subsec:standards}
\plt{Coding, documentation, interface or safety standards the project will
follow, and legal or regulatory factors such as licensing, intellectual
property, and data privacy. Cite each standard.}

\noindent\textbf{Standards:}
\begin{itemize}
    \item \textbf{API compatibility} -- Lake's inference API will follow the OpenAI API endpoints for requests and response formats, as specified in S.3.
    \item \textbf{Coding conventions} -- Black code style and Ruff lint checks will be used for Python components. Rustfmt and Clippy will be used for Rust components Prettier and ESLint will be used for Typescript components.
\end{itemize}

\noindent\textbf{Legal and Regulatory Factors:}
\begin{itemize}
    \item \textbf{Software licensing} -- Lake is available under the GNU GPL v3.0 license. All dependencies used in Lake must be compliant and compatible with Lake's intended use and distribution.
    \item \textbf{Model licensing} -- Pretrained LLMs used for inference are subject to its respective licenses. Lake must be compliant with these licenses for its use and distribution.
\end{itemize}
